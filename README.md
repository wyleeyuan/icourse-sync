# icourse 语音课件同步

把复旦大学智慧教学资源平台（[icourse.fudan.edu.cn](https://icourse.fudan.edu.cn)）的
**「语音课件」**增量同步到本地。

产物是一份 Word：**课件录屏截图 + 带时间轴的语音识别原文**，按文档顺序时间对齐 ——
相当于把一节课的回放压成一份可以翻、可以搜的字幕稿。

```
00:00:26  [课件截图]
00:01:14  [课件截图]
00:01:26  嗯，我们上次讲到了……
...
```

## 快速开始

### 方式一：双击（推荐，不用记命令）

装好 Python 后，直接双击 `scripts/` 下对应你系统的那个：

| 系统 | 双击这个文件 |
|---|---|
| macOS | `同步课件.command` |
| Windows | `sync-courseware.bat` |

窗口会显示进度，跑完停住等你按键，配置和目录都不用管。

> macOS 首次双击若提示「来自身份不明的开发者」：右键点它 → 选「打开」→ 确认一次，
> 之后就正常了。

### 方式二：命令行

```bash
git clone <this-repo> && cd icourse-sync

pip install browser-cookie3          # 可选，但强烈建议：能直接读浏览器 Cookie
cp config.example.json config.json
# 打开 config.json，把 dest 改成你想存的地方

python3 src/icc_sync.py --dry-run    # 先看一眼要做什么
python3 src/icc_sync.py              # 正式同步
```

Python 3.9+。首次运行前请确保 **Edge 或 Chrome 已经登录过 icourse** ——
脚本会自己从浏览器取登录态并固化下来，之后就不需要浏览器了。
不装 `browser-cookie3` 也能跑，此时登录态退回 `bsk` 路线（见「登录态」）。

> **Windows 用户请注意**：Chrome / Edge 自 127 版起启用了 App-Bound Encryption，
> 第三方程序**无法**再读取它们的 Cookie（`browser-cookie3` 会报
> `Unable to get key for cookie decryption`）。macOS / Linux 不受影响。
> Windows 上请改用 `cookie.txt` 方案，见下一节的窗口「手动粘贴 Cookie」。

## 配置

只有一个文件 `config.json`，**通常只需要改 `dest`**：

| 键 | 默认 | 说明 |
|---|---|---|
| `dest` | `~/Desktop/语音课件` | **产物目录，唯一需要关心的** |
| `courses.include` | `[]` | 只同步这些课（子串匹配，不区分大小写）；空 = 全部 |
| `courses.exclude` | `[]` | 排除这些课，比如误选的旁听课 |
| `auth.source` | `auto` | 登录态来源，见下节 |
| `auth.browser` | `edge` | 从哪个浏览器读 Cookie，可写成 `["edge","chrome"]` |
| `retry_fallback_days` | `7` | 已降级为拆分兜底的课次，隔几天自动重试一次「升级回合并版」 |
| `tenant_code` | `222` | 复旦的租户号 |

不打算同步某门课（旁听课、不需要复习的课）就填 `exclude`，写课名的**任意片段**即可，多个词任一命中都会排掉：

```json
{
  "dest": "~/Desktop/语音课件",
  "courses": {
    "include": [],
    "exclude": ["体育", "军事理论", "某门不想要的课"]
  }
}
```

> ⚠️ 关键词写到能唯一区分就够了，**别写太短**（`"马"` 会波及任何带"马"的课名）；
> 也不必抄全名 —— 课名若临时改了副标题、加了"（研讨）"，写片段反而更稳。

产物布局：`<dest>/<课程名>/<课程名>_<课次>_语音课件.docx`

```
~/Desktop/语音课件/
├── 高级软件开发技术/
│   └── 高级软件开发技术_2026-09-11第11-12节_语音课件.docx
├── 程序分析/
│   ├── 程序分析_2026-09-09第11-13节_语音课件.docx
│   └── 程序分析_2026-09-16第11-13节_语音课件.docx
└── ...
```

早期平铺在根目录的旧文件，脚本启动时会自动迁进对应课程文件夹。

## 常用命令

| 命令 | 作用 |
|---|---|
| `python3 src/icc_sync.py` | 按配置增量同步 |
| `--login` | 现场登录：打开浏览器 → 你登录 → 自动读取并固化 Cookie |
| `--dry-run` | 只报告计划，**不调导出接口** |
| `--list` | 列出全部可导课次及本地状态（完整 / 待修复 / 缺失） |
| `--course 程序分析` | 只同步指定课程（可重复） |
| `--dest ~/other` | 临时覆盖目标目录 |
| `--auth cookie` | 临时指定登录态来源 |
| `--no-repair` | 关闭修复路径，锁死课次直接落拆分兜底 |
| `--force` | 忽略本地文件全部重导（⚠️ 见「使用须知」） |

脚本是**幂等**的：重复跑不会重复下载已有完整文件，可以放心定时执行。

## 登录态

脚本自己不抓包：它从你**已经登录的那个浏览器**里读出该站点的 Cookie
（含 HttpOnly 的会话票），固化到 `cookie.txt`，之后纯 HTTP 请求即可 ——
不用浏览器一直开着，也不用每次开浏览器会话。

| 值 | 做法 | 特点 |
|---|---|---|
| `cookie.txt` | 读项目根里固化的 Cookie | 最快，零额外依赖 |
| `browser` | 用 `browser-cookie3` 从本地 Edge/Chrome 读 | 自动刷新，不用手工 |
| `bsk` | 复用 [BrowserSkill](https://www.npmjs.com/package/bsk) 的浏览器会话 | 零依赖兜底，但每次要开浏览器 |
| `cookie` | 只认 `cookie.txt`，不回落 | 手动粘贴 Cookie 时用 |

`auto`（默认）的顺序是 **`cookie.txt` → 本地浏览器 → `bsk`**，每个候选都做一次
真实鉴权验证，**第一个通的即采用** —— 前面能用就绝不会碰到后面（尤其不会白开浏览器）。

`cookie.txt` 过期时会**自动降级**去读浏览器，读到新的再覆盖回来，所以正常情况下
你什么都不用做。

只有连浏览器里都没有有效 Cookie 时，才需要现场登录一次：

```bash
python3 src/icc_sync.py --login
```

它会用 Edge 打开 icourse，等你在浏览器里登录完按回车，然后自动读取、验证并固化。

> ⚠️ 脚本只读 **Edge / Chrome** 的 Cookie 库（macOS 的 Safari 受沙盒限制读不到），
> 所以请在这两个浏览器里登录 —— 在哪个浏览器登录，脚本就从哪个浏览器读。

### 手动粘贴 Cookie（Windows 推荐，也是万能兜底）

任何平台上，只要浏览器那条路读不到，都可以手工来一次。**一次操作、长期有效**
（脚本会把它固化在 `cookie.txt`，直到登录自然过期）：

1. 用 Edge 或 Chrome 打开 <https://icourse.fudan.edu.cn>，确认已经登录
2. 按 `F12` 打开开发者工具，切到 **Network / 网络** 标签
3. 刷新页面，在请求列表里随便点一个 `icourse.fudan.edu.cn` 的请求
4. 在右侧 **Headers / 标头 → Request Headers / 请求标头** 里找到 `Cookie:` 那一行
5. 右键 → Copy value（复制值），把整条值拷下来
6. 在项目根目录新建纯文本文件 `cookie.txt`，把内容粘进去保存

然后正常跑同步，日志里会显示 `后端：cookie` 就说明生效了。
脚本会自动清理空白，所以直接整条粘贴即可，不用管首尾空格。

> ⚠️ `cookie.txt` 等价于你的登录凭证，别发给任何人。
> `.gitignore` 已经拦住了它，不会上传到仓库。

## 工作原理

```
枚举课次 → 比对本地已有哪些 → 预检语音识别就绪 → 触发导出 → 轮询 → 下载校验
                                            │
                          空壳则逐级降级：type=1,2,3 剥译文 → type=1,2,4 → 仍不行才落拆分兜底
```

四个设计点值得说明：

**1. 增量**：本地文件本身即状态，没有额外的数据库。已完整的课次一个接口都不调。

**2. 导出前必须预检，不靠"等几天"猜**：平台的导出任务按 `(课次, type 参数)` 在服务端缓存。
**如果在语音识别跑完之前导出过，那份空壳就被永久锁死** —— 之后等多久、重试多少次，
返回的都是同一份旧文件，且没有接口能刷新。

所以脚本每次都在触发导出前查一次字幕是否就绪（`search-trans-result`），没就绪**直接跳过不导**，
下次运行自动再来。判不准（预检接口异常）时同样一律不导 —— 宁可这次不导，
也不要把空壳种进缓存。就绪状态是唯一判据，不猜时间。

**3. 空壳不落盘**：下载先到临时文件，校验通过才移进目录。
校验是数文本：时间轴条数与含中文的段落数，满足 `中文段 ≥ 20` 且 `中文段/时间轴 ≥ 0.15` 才算完整。
光看文件大小分辨不出来 —— 空壳同样有截图和时间轴，只是没有一句字幕。

**4. 已被锁死的课次也能救回来**：改用**另一个缓存 key** 重新生成。脚本按 `1,2,3` → `1,2,4`
的顺序逐个试，任一成功即停：

- `type=1,2,3` 比 `1,2` 多一份译文；译文段在文档里与原文段交替排列、样式完全相同，
  可以按「语言 + 位置」精确剥掉，得到与原生 `1,2` 等价的合并版。
- `type=1,2,4` 多一份 AI 摘要，实测导出成 Word 时没混进正文，下载即用。

⚠️ **一个课次可能多个 key 先后被污染**（同一节在语音识别跑完前被导出过两次就会这样，
实测 `sub_id=662773` 的 `1,2` 与 `1,2,3` 双双锁死），所以是「逐个试」而不是「只试一个」。
换 `type` 的**写法变体**（`2,1`、`1, 2`、`01,02`…）则没有用 —— 服务端会规范化成同一个 key。

三级降级：

| 层级 | 做法 | 产物 |
|---|---|---|
| 1 | `type=1,2` 原生导出 | `<课程>_<课次>_语音课件.docx` |
| 2 | `type=1,2,3` + 本地剥译文，失败再试 `type=1,2,4` | 同上（形态等价） |
| 3 | `type=2` + `type=1` 拆分兜底 | `_字幕.docx` + `_课件.pptx` |

第 2 层成功后会**自动清掉该课次遗留的兜底产物**，目录里只留最好的形态。
只有掉到第 3 层才会产生 `.pptx`。

详细机制、接口契约与全部实测记录见 `notes/api.md`
（本地技术文档，**已 gitignore，不随仓库上传**）。

## 项目结构

```
src/icc_sync.py            命令行入口 + 主流程编排
src/iccourse/              实现部分，按职责拆开
├── config.py              配置与全局常量
├── api.py                 接口契约（URL 构造 / 浏览器侧 JS / 响应提取器）
├── backends.py            请求后端（bsk 借浏览器会话、cookie 纯 HTTP）
├── auth.py                登录态（读浏览器 Cookie、固化 cookie.txt、现场登录）
├── documents.py           产物校验与清洗（docx/pptx 完整性、剥掉译文段）
├── paths.py               产物命名与覆盖判定
└── transfer.py            导出触发 / 轮询 / 下载 / 落盘
notes/                     本地技术文档，gitignore 不上传
├── api.md                 接口契约、type 语义、缓存锁定、空壳判据、踩坑记录
└── 使用手册.md             手动操作速查（双击启动 / 命令行 / 常见问题）
config.example.json        配置模板
scripts/                   双击启动器
├── 同步课件.command         macOS
└── sync-courseware.bat     Windows
```

整条链路只依赖标准库；`browser-cookie3` 是**可选增强** —— 装了就能直接从浏览器
读 Cookie 走纯 HTTP 同步，不装则自动退回 `bsk` 路线（仍可用，但需要浏览器常驻）。

## ⚠️ 使用须知

- 复旦这个实例把「导出课件」功能**对学生是关闭的**（后端下发 `sub_is_export = "2"`，
  前端因此不渲染导出按钮）。脚本能跑通是因为后端接口只校验登录态、不校验该权限 ——
  也就是说，**这属于绕过前端权限控制，而不是使用平台提供的导出功能**，请自行确认是否符合学校平台规范。
- 每次导出会推高服务端 `download_num` 计数。所以默认行为是**只补差异**，
  不建议改用 `--force` 全量重导。
- 产物下载链接在有效期内是**公网可读**的，别外发。
- 课件内容版权归授课教师与学校所有，仅供个人学习使用。

## 排错

| 现象 | 原因 |
|---|---|
| `枚举课次失败：HTTP 401` | 登录态失效。`auto` 下会自动降级重试；降到 `bsk` 也不通时跑一次 `--login` |
| 日志出现「登录态无效…换下一个来源」 | `cookie.txt` 已过期，正在自动改用浏览器 Cookie（读到就覆盖回去，属正常流程） |
| 一直报「等待识别」 | 源站语音识别还没跑完，过几小时再跑一次 |
| 某节走「修复路径」 | 该 `(课次, "1,2")` 历史上已被锁死，脚本依次用 `1,2,3`、`1,2,4` 重新生成 |
| 某节落到拆分兜底 | 所有修复 key 都不可用，只剩 `_字幕.docx` + `_课件.pptx`；默认 7 天后才自动重试 |
| `找不到可用的登录态` | 三条来源都不通，按提示跑 `--login` |
| Windows 报 `Unable to get key for cookie decryption` | Chrome/Edge 127+ 的 App-Bound Encryption 限制，并非脚本故障；改用「手动粘贴 Cookie」 |
| Windows 双击 `.bat` 一闪而过 / 提示没有 Python | 没装 Python 或安装时没勾 PATH；重装并勾选 `Add python.exe to PATH` |
