# icourse 语音课件同步

把复旦大学智慧教学资源平台（[icourse.fudan.edu.cn](https://icourse.fudan.edu.cn)）的
**「语音课件」**增量同步到本地。

产物是一份 Word：**课件录屏截图 + 带时间轴的语音识别原文**，按文档顺序时间对齐 ——
相当于把一节课的回放压成一份可以翻、可以搜的字幕稿。

```
00:00:26  [课件截图]
00:01:26  嗯，我们上次讲到了……
...
```

**一个文件，零第三方依赖**，只用系统自带的 Python。

## 快速开始

### 双击（推荐）

双击项目根目录的 **`一键同步.command`**。它会：

1. 校验 `cookie.txt` 里的登录态还有没有效
2. 比对本地已有文件，只补缺失的课次
3. 跑完停住等你按键，窗口不会一闪而过

> 首次双击若提示「来自身份不明的开发者」：右键点它 → 选「打开」→ 确认一次，之后就正常了。

### 命令行

```bash
python3 icourse_sync.py             # 增量同步
python3 icourse_sync.py --check     # 只校验 cookie.txt 有效不有效
python3 icourse_sync.py --dry-run   # 只列计划，不触发导出
```

## 登录态：粘一次 Cookie，长期有效

脚本**不碰浏览器**，只读项目根目录的 `cookie.txt`（内容是整条 `Cookie` 请求头）。
取一次能用很久，过期了再取一次即可。

1. Chrome 打开 <https://icourse.fudan.edu.cn/education/?tenant_code=222>，确认已登录
2. 按 `F12` → 切到 **Network / 网络** → 按 `⌘R` 刷新页面
3. 在请求列表里随便点一条 `icourse.fudan.edu.cn` 的请求
4. 右侧 **Headers → Request Headers**，拉到底部找到 **`Cookie:`** 那一行
5. 在它的**值**上右键 → **Copy value**
   （找不到就用这个更稳的：在请求上右键 → **Copy → Copy as cURL**）
6. 把内容整条粘进项目根目录的 `cookie.txt`，保存

> `General` 那块里的 `Request Method: GET` 不是我们要的；
> `Request Headers` 里 `Cookie:` 上面那几行（`Accept`、`Referer` 之类）也都不用管 —— **只认 `Cookie:` 那一行**。

**怎么判断还有效**：跑 `python3 icourse_sync.py --check`，或者直接双击启动器 ——
第一行会告诉你 `✓ cookie.txt 有效，可见 N 条课次`。失效了按上面重做一遍。

> ⚠️ `cookie.txt` 等于你的登录凭证，别发给别人。`.gitignore` 已经拦住它，不会进仓库。
> 里面的 `_token` 是个 JWT，通常隔天前后过期 —— 所以**偶尔要重取一次是正常现象**。

## 配置

可选文件 `config.json`，**通常只需要改 `dest`**：

```json
{
  "dest": "~/Documents/语音课件",
  "courses": { "include": [], "exclude": [] }
}
```

| 键 | 默认 | 说明 |
|---|---|---|
| `dest` | `~/Documents/语音课件` | 产物目录 |
| `courses.include` | `[]` | 只同步这些课（子串匹配，忽略大小写）；空 = 全部 |
| `courses.exclude` | `[]` | 排掉这些课，比如旁听课 |

> 关键词写到能唯一区分就够了，别写太短（`"马"` 会波及任何带「马」的课名）。

产物布局：`<dest>/<课程名>/<课程名>_<课次>_语音课件.docx`

## 常用命令

| 命令 | 作用 |
|---|---|
| `python3 icourse_sync.py` | 增量同步 |
| `--check` | 只校验 `cookie.txt` 是否有效 |
| `--dry-run` | 只报告计划，**不调导出接口** |
| `--course 程序分析` | 只同步指定课程（可重复） |
| `--dest ~/other` | 临时覆盖目标目录 |
| `--force` | 忽略本地文件全部重导（⚠️ 见「使用须知」） |

脚本是**幂等**的：重复跑不会重复下载已有完整文件，可以放心定时执行。

## 工作原理

```
校验 Cookie → 枚举课次 → 比对本地 → 预检语音识别就绪 → 触发导出 → 轮询 → 下载校验
                                          │
                          空壳则换缓存 key 重取：type=1,2,3（剥译文）→ type=1,2,4
```

**1. 增量**：本地文件本身即状态，没有额外数据库。已完整的课次一个接口都不调。

**2. 导出前必须预检**：平台的导出任务按 `(课次, type)` 在服务端缓存，
**如果在语音识别跑完之前导出过，那份空壳就被永久锁死** —— 之后等多久、重试多少次，
返回的都是同一份旧文件。所以脚本每次都在触发导出前先查一次字幕是否就绪，没就绪**直接跳过不导**，
下次运行自动再来。就绪状态是唯一判据，不猜时间。

**3. 空壳不落盘**：下载先到临时文件，校验通过才移进目录。校验是数文本 ——
时间轴条数与含中文的段落数满足 `中文段 ≥ 20` 且 `中文段/时间轴 ≥ 0.15` 才算完整。
光看文件大小分辨不出来：空壳同样有截图和时间轴，只是没有一句字幕。

**4. 锁死的课次也能救回来**：改用**另一个缓存 key** 重新生成，按 `1,2,3` → `1,2,4` 逐个试。
`type=1,2,3` 比 `1,2` 多一份英文译文，可以按「语言 + 位置」精确剥掉，得到与原生等价的合并版；
`type=1,2,4` 多一份 AI 摘要，导出成 Word 时没混进正文。换 `type` 的**写法变体**（`2,1`、`1, 2`）没用 ——
服务端会规范化成同一个 key。

## ⚠️ 使用须知

- 复旦这个实例把「导出课件」功能**对学生是关闭的**（后端下发 `sub_is_export = "2"`，前端因此不渲染按钮）。
  脚本能跑通是因为后端接口只校验登录态、不校验该权限 —— 也就是说，
  **这属于绕过前端权限控制，而不是使用平台提供的导出功能**，请自行确认是否符合学校平台规范。
- 每次导出会推高服务端 `download_num` 计数，所以默认只补差异，不建议 `--force` 全量重导。
- 产物下载链接在有效期内是**公网可读**的，别外发。
- 课件内容版权归授课教师与学校所有，仅供个人学习使用。

## 项目结构

```
一键同步.command        双击入口：校验登录态 → 增量同步
icourse_sync.py         全部逻辑（单文件、纯标准库）
config.json             可选配置，一般只改 dest（已 gitignore）
cookie.txt              登录态，手动粘贴（已 gitignore）
```

## 排错

| 现象 | 原因 / 处理 |
|---|---|
| 提示 `cookie.txt 缺失或已失效` | 按上面「粘一次 Cookie」重做一遍 |
| 一直报「等待识别」 | 源站语音识别还没跑完，过几小时再跑一次即可 |
| 某节走「修复路径」 | 该课次的 `1,2` 缓存历史上已被锁死，脚本自动换 key 重取，属正常 |
| `--dry-run` 列了但没下载 | 那是预览模式，去掉 `--dry-run` 才会真导出 |
| 双击报「来自身份不明的开发者」 | 右键 → 打开 → 确认一次 |
| 双击后提示找不到 python3 | `xcode-select --install` 装一下命令行工具 |
